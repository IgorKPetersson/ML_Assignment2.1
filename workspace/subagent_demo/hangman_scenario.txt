Fake Hangman Scenario For Sub-Agent Testing

Goal:
Build a small command-line Hangman game.

Basic requirements:
- The game chooses one secret word from a short safe word list.
- The player guesses one letter at a time.
- Correct guesses reveal matching letters.
- Wrong guesses reduce remaining attempts.
- The player wins when all letters are revealed.
- The player loses when attempts reach zero.

Current rough plan:
- Store the secret word as lowercase text.
- Store guessed letters in a list.
- For each player guess, check whether the letter is in the word.
- If the guess is not in the word, subtract one attempt.
- Print the current masked word after each guess.

Known uncertainty:
- It is unclear how the game handles repeated guesses of the same wrong letter; recommended to not reduce attempts for repeated wrong guesses and notify the player.
- The handling of uppercase input is unspecified; ideally, input should be normalized to lowercase for consistency.
- Behavior for non-letter inputs is undefined; the game should reject or gracefully handle such inputs.
- Timing for checking win/loss states is not detailed; it should occur after each guess to update game status promptly.

Acceptance Criteria:
- Repeated guesses of the same wrong letter do not reduce attempts and notify the player.
- Uppercase and lowercase inputs are treated equivalently by normalizing input.
- Non-letter inputs are rejected with an appropriate message without penalty.
- Win or loss state is evaluated immediately after each guess and game ends accordingly.
